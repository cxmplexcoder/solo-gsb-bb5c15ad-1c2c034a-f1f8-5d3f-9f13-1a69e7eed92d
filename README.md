# 无线麦克风频率协调工具

面向现场音频工程师的无线麦克风频率协调 Web 应用。录入设备频率后自动分析互调冲突，并在指定约束下自动协调出无冲突、总偏移最小的频率方案，支持方案保存与回放。

## 功能

- **设备管理**：录入最多 8 个设备（名称、工作频率 MHz、保护间隔 MHz），可锁定频道、编辑、删除
- **互调冲突分析**：对任意两个不同频道枚举 `|f1−f2|`、`f1+f2`、`|2f1−f2|`（含两种有序组合），标出落入任一频道保护区（载频 ± 保护间隔，含边界）的互调积，并显示来源频道对与受影响频道
- **自动频率协调**：在指定频段、步进、最大偏移内调整未锁定频道（锁定频道保持不动），通过回溯搜索找出**总偏移最小**的无冲突方案；总偏移相同时按录入顺序选择更低频率；无解时保持原值并说明原因
- **现场占用频段避让**：协调前可临时填写多个现场扫描到的占用区间（MHz，仅作为本次协调参数提交，不改动设备数据）；候选频道新载频的保护区与任一占用区间相交（端点相接也算）即不可用，重叠区间自动合并，实际避让的区间会随结果展示并记入保存的方案
- **方案管理**：保存协调方案、查看详情、**应用前预览 → 凭据确认两步应用**、删除
- **应用安全**：应用已保存方案前必须先预览，服务端按设备 id 核对当前频率与目标频率，复算互调冲突与占用区间相交；确认时在同一 SQLite 事务内核对凭据、重做检查并一次性写入，设备状态变化或凭据缺失一律拒绝且不写入任何设备
- **持久化**：SQLite 存储设备与方案，容器重启不丢失

## 快速开始（Docker，单条命令）

```bash
docker compose up --build
```

启动后访问：**http://localhost:3000**

> 数据库首次启动时自动初始化（`CREATE TABLE IF NOT EXISTS`），无需额外迁移步骤。
> SQLite 数据文件存放在命名卷 `app-data` 中；停止容器可用 `docker compose down`。

### 配置（环境变量，均为可选）

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `PORT` | `3000` | 服务监听端口，浏览器访问 http://localhost:3000 |
| `DATA_DIR` | `./data`（容器内 `/app/data`） | SQLite 数据库目录，Compose 已挂载命名卷持久化 |
| `APPLY_SECRET` | 未设置（每次启动随机生成） | 方案应用确认凭据的 HMAC 签名密钥；不设置时服务重启后旧凭据失效（需重新预览），多副本部署时可设为共享密钥 |

## 使用说明

1. **录入设备**：在「设备列表」中填写名称、频率（如 `512.000`）、保护间隔（默认 `0.25` MHz），可勾选锁定。也可点击「载入示例」快速填充 8 通道示例数据。
2. **查看冲突**：冲突分析随设备变更自动刷新，表格列出互调类型、互调积频率、来源频道、受影响频道及偏差。
3. **自动协调**：设置频段上下限、步进（如 `0.025` MHz = 25 kHz）、最大偏移；如有现场扫描到的占用频段，点「+ 添加占用区间」逐行填写下限与上限（MHz，如 `511.700`–`513.000`，可添加多行；整行留空自动忽略），再点「开始协调」。成功后可将结果「应用到设备」或「保存方案」。
4. **占用频段说明**：占用区间只随本次协调请求提交，不会修改任何设备数据；区间要求为有限数值且下限不大于上限，重叠或端点相接的区间会自动合并。只要某频道新载频的保护区（新频 ± 保护间隔）与任一占用区间相交（端点相接也算），该候选即不可用；其余候选仍按原有互调规则与总偏移排序求解。结果页会列出**实际参与避让的（合并后）区间**。若因此无解，会明确说明占用频段限制，所有频道保持原频率。
5. **方案回放（两步应用）**：在「已保存方案」中展开历史方案（含当时使用的占用区间参数），点击「应用前预览」。预览会按设备 id 列出**当前频率 → 目标频率**，并用各设备**当前保护间隔**复算目标配置的互调冲突、检查保护区与方案所存占用区间的闭区间相交；任一检查失败会列明全部原因且不提供确认入口。检查通过后点击「确认应用」，服务端在**同一个 SQLite 事务**内核对确认凭据（绑定方案内容与全部设备状态）、重做全部检查并一次性写入；若预览后设备状态发生变化、方案被改动或凭据缺失/无效，返回 `409` 且**不写入任何设备**，界面提示重新预览。

## 协调算法

- 每个未锁定频道的候选频率为 `原频 ± k × 步进`（`k × 步进 ≤ 最大偏移`），且必须落在指定频段内
- 现场占用频段：候选载频 `f` 的保护区 `[f − guard, f + guard]` 与任一（已合并的）占用区间相交即剔除该候选，闭区间判定、端点相接也算相交
- 搜索目标：所有频道总偏移 `Σ|新频 − 原频|` 最小；同分时按录入顺序逐频道比较，取更低频率
- 采用带回溯的分支限界搜索，随频道逐个确定增量检查互调积；设节点上限（200 万）防止极端参数下搜索爆炸，触顶时返回当前最优并明确标注
- 无解时所有频道保持原值，并返回可读的原因说明

## API 概览

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/devices` | 设备列表 |
| POST | `/api/devices` | 新增设备（最多 8 个） |
| PUT | `/api/devices/:id` | 更新设备 |
| DELETE | `/api/devices/:id` | 删除设备 |
| GET | `/api/conflicts` | 当前配置的互调冲突列表 |
| POST | `/api/coordinate` | 自动协调（body：`bandMin/bandMax/step/maxOffset`，单位 MHz；可选 `occupiedBands: [{lo, hi}, …]` 现场占用区间 MHz，服务端校验有限数值与 `lo ≤ hi` 并自动合并重叠/相接区间） |
| GET / POST | `/api/plans` | 方案列表 / 保存方案 |
| DELETE | `/api/plans/:id` | 删除方案 |
| POST | `/api/plans/:id/preview` | 应用前预览：校验已求解/一一对应/目标频率合法/锁定不改频，用当前保护间隔复算互调冲突并检查与占用区间闭区间相交；成功返回当前→目标频率明细及确认凭据 `credential`；检查失败返回 422 并列明全部原因 |
| POST | `/api/plans/:id/apply` | 确认应用：body 须含 `{ "credential": "…" }`；同一 SQLite 事务内核验凭据、重做全部检查并一次性更新。凭据缺失/无效、方案内容或设备状态与预览不一致、复查失败均返回 409（`needRepreview: true`）且不写入任何设备 |
| POST | `/api/seed` | 空库时载入示例数据 |

## 技术栈

Node.js 20 · Express 4 · better-sqlite3（WAL 模式）· 原生 HTML/CSS/JS（无前端框架）

```
├── server.js            # Express 服务与 API 路由
├── db.js                # SQLite 连接与建表
├── lib/intermod.js      # 互调计算与自动协调核心（纯函数，可独立测试）
├── public/              # 前端页面（index.html / app.js / style.css）
├── test/                # 核心算法与方案应用两阶段流程测试（node:test）
├── Dockerfile
└── docker-compose.yml
```
